Architecture: Two-Tier Incident Response

KubeMedic uses a deterministic rule-based Tier 1 combined with an LLM-powered Tier 2 for safe, impact-aware Kubernetes operations with Many-to-One ticket correlation.

Tier 1: MCP Server (Cheap Watcher)
  • Rule-based evidence collection (24/7, no AI cost)
  • Provides read-only K8s tools to the agent
  • Creates ticket storm when anomaly detected
  • NEVER reasons, diagnoses, or makes decisions
Tier 2: IBM Bob Agent (AI Brain)
  • Correlates multiple tickets → 1 Master Incident
  • Gemini LLM for hypothesis generation
  • Impact-aware remediation plan (blast radius, reversibility)
  • Wakes up ON-DEMAND only (prevents token drain)

Key Principles (C3 + C4 Framework)

  • Many-to-One Correlation: Bob groups cascading alerts into a single Master Incident with one root-cause fix.
  • Impact-Awareness (C3): Every plan includes risk level, reversibility, blast radius, and user-facing risk.
  • Approval Gate: Mutating actions require explicit human approval. One approval resolves ALL correlated tickets.
  • Dual-Signal Verification (C4): Success confirmed by K8s rollout readiness AND application /health HTTP 200.
